Day 95 of 100

Deep Dive: RAG Over Your Trading Journal

Tonight you'll be able to: point Day 59’s RAG at your trading journal and make it answer “why did I do that?” from your own entries — an exact metadata filter in front of the fuzzy ranker, event windows for time questions, and a refusal gate that can fire before ranking even starts.

The one idea

Day 59’s RAG treated its corpus as prose: chunk it, rank everything by word overlap, gate on the best score. A trading journal is not prose. Every entry your tradebot collects is a record — a date, a ticker, an action, and the reason you typed at the time — and records break the doc design in three specific places. Today’s build fixes each one. The journal in the code is fictional: 24 invented entries in your journal’s format, standing in for the real thing. None of them are real trades; the format and the machinery are the lesson.

Fix 1: an exact stage in front of the fuzzy one. A question that names a ticker or a month is not a similarity question — it is a WHERE clause. So retrieval becomes two-stage: stage 1 filters on metadata (ticker, date) deterministically, and Day 59’s TF-IDF ranker only ever sees the survivors. Part 2 prints the receipt. Asked “was the trim about the thesis or about position size” over all 24 entries, the #1 hit is a PLTR buy at 0.2403 — its note says “sizing up”, which is word-near the question and factually the wrong trade. The actual trim entry ranks #2 at 0.2228. Now the subtle part: inside the META slice, that same entry still scores exactly 0.2228. The filter did not make the right answer score higher by a single point — it made the wrong answers impossible. That is the whole argument for hybrid retrieval: spend determinism on the parts of the question that are exact, and reserve the fuzzy machinery for the part that is genuinely fuzzy.

Fix 2: events get windows, not just matches. “Why did I exit META in October?” The October filter finds three entries and the sell among them is the anchor — but the meaning of the exit lives around it: the September trim that started the reduction, the Oct 7 note where the exit triggers were written down in advance, the Oct 26 post-exit review that drew the rule from it. So the system expands the anchor into a window on META’s own timeline — two entries before, one after — deliberately reaching outside the month filter that found it. The filter’s job is to locate the event; the window’s job is context, and context is not bound by the filter.

Fix 3: the gate moves earlier, because the corpus is you. Day 59’s gate sat after ranking: best score too low, refuse. The journal adds a gate before ranking: if stage 1 returns zero rows, stage 2 never runs. Q3 asks why you bought the COIN dip; this journal has never traded COIN, the filter returns 0 of 24, and the system refuses at the index — there is nothing to rank and nothing to remember. Why be stricter here than over lesson notes? A hallucinated cake temperature is a wrong fact about the world. A hallucinated reason you sold is a false memory about your own decisions — and future-you, reading it back in a review, would quote it as fact. The cost asymmetry justifies the extra gate. (One repair from Day 59 falls away, honestly: no chunking. An entry is already atomic, so the row is the chunk, and the citation changes shape to match: [2026-09-15 META trim] instead of [doc#chunk].)

Analogy

It is the difference between grep and a database. Day 59 grepped prose, because prose has no schema to exploit. The journal is a table: ticker and date are the index, the note is the payload. You would never full-text-scan a table for rows an index can hand you — you use the structure the data already has, and save the expensive fuzzy machinery for the one column that is actually fuzzy. And the pre-ranking refusal is a miss with correct semantics: NOT FOUND at the index layer, so the ranking tier is never consulted. Same shape as your storage reads — the cheap, exact layer gets to say “not here” before the expensive layer wakes up.

See it

Two-stage retrieval over the journal. Stage 1 (blue) is an exact metadata filter — and the only stage that can refuse before ranking (Q3). Stage 2 (green) is Day 59’s TF-IDF ranker, now confined to the surviving slice, with the score gate at its exit. Event questions branch sideways into a window (purple): the anchor’s neighbours on the ticker’s own timeline, filter be damned.

Code it (~30 min)

Standard library only, like Day 59 — run it in ~/ai-lab with python3 code.py. Part 1 loads the 24 fictional entries and builds Day 59’s TF-IDF index over them, one row per entry; the indexed text includes the metadata as words (ticker, action, month name) so the fuzzy ranker can hear “September” — the filter remains the exact path. Part 2 runs one question both ways: ranked over the whole journal, then inside the META slice. Part 3 is the payoff: Q1 answered by a single verbatim sentence with its citation; Q2’s window printed around the >> anchor; Q3 refused at stage 1 with stage 2 skipped. On your machine, the same three functions take your real journal export — the fictional rows are the only thing that changes.

def tokenize(text):
    """Lowercase word tokens; punctuation is dropped. (Day 59, verbatim.)"""
    return re.findall(r"[a-z0-9]+", text.lower())


MONTHS = ["january", "february", "march", "april", "may", "june",
          "july", "august", "september", "october", "november",
          "december"]


def entry_text(e):
    """What the index sees: the note, plus the metadata as words -
    ticker, action, and the month name - so 'September' is
    searchable text too. The stage-1 filter stays the exact path;
    this only helps the fuzzy ranker."""
    month = MONTHS[int(e["date"][5:7]) - 1]
    return f"{e['ticker']} {e['action']} {month} {e['note']}"


def entry_id(e):
    """The journal citation: one exact row. [2026-09-15 META trim]"""
    return f"{e['date']} {e['ticker']} {e['action']}"

entry_tokens = [tokenize(entry_text(e)) for e in JOURNAL]
vocab = sorted({t for toks in entry_tokens for t in toks})
V = {w: i for i, w in enumerate(vocab)}
N = len(JOURNAL)
df = Counter()
for toks in entry_tokens:
    df.update(set(toks))
idf = {w: math.log((1 + N) / (1 + df[w])) + 1.0 for w in vocab}


def embed(tokens):
    """TF-IDF vector: count of each word, weighted by its idf.
    (Day 59, verbatim.)"""
    counts_ = Counter(tokens)
    vec = [0.0] * len(vocab)
    for w, c in counts_.items():
        if w in V:                       # unknown words are ignored
            vec[V[w]] = c * idf[w]
    return vec


index = [embed(toks) for toks in entry_tokens]
print(f"  vocabulary = {len(vocab)} terms; index shape: "
      f"{len(index)} entry vectors x {len(vocab)} dims")


def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb) if na and nb else 0.0


# ---------- The two stages --------------------------------------------------
def stage1_filter(ticker=None, month=None):
    """STAGE 1 - exact metadata filter. Returns journal indices.
    Deterministic: a row matches or it does not. No scores."""
    return [i for i, e in enumerate(JOURNAL)
            if (ticker is None or e["ticker"] == ticker)
            and (month is None or e["date"][5:7] == month)]


def stage2_rank(query, subset, k=K):
    """STAGE 2 - Day 59's TF-IDF cosine rank, INSIDE the slice only."""
    qv = embed(tokenize(query))
    scored = [(cosine(qv, index[i]), i) for i in subset]
    scored.sort(key=lambda p: (-p[0], p[1]))
    return scored[:k]


def sentences(text):
    return [s for s in re.split(r"(?<=[.!?])\s+", text) if s]


def extract_answer(query, hits, n=2):
    """Extractive assembly, Day 59's rules with one journal
    twist: lift the best COMPLETE sentences from the TOP
    entry's note only, verbatim, each printed with its
    [date TICKER action] citation. Day 59 read the top 2
    chunks because a chunk is a fragment of a document;
    a journal entry is a complete record of one event,
    so the answer quotes the event itself."""
    qtoks = set(tokenize(query))
    cands = []
    for _, i in hits[:1]:
        for si, sent in enumerate(sentences(JOURNAL[i]["note"])):
            if not (sent[0].isupper() and sent[-1] in ".!?"):
                continue                 # a fragment, not a sentence
            shared = qtoks & set(tokenize(sent))
            s = sum(idf[w] for w in shared if w in idf)
            if s > 0:
                cands.append((s, i, si, sent))
    if not cands:
        return []
    floor = 0.4 * max(s for s, _, _, _ in cands)
    strong = [c for c in cands if c[0] >= floor]
    strong.sort(key=lambda t: (-t[0], t[1], t[2]))
    picked = sorted(strong[:n], key=lambda t: (t[1], t[2]))
    return [(sent, entry_id(JOURNAL[i])) for _, i, _, sent in picked]
